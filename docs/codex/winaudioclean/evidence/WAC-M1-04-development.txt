Implementation and corrections
- Lazy native declarations preserve import safety in Windows PowerShell 5.1
  and PowerShell 7. No compilation, native process or filesystem work occurs
  merely from importing the helper.
- CreateNew reserves a unique partial in the destination. A source read lock
  remains held through reporting. Canonical paths resolve junction aliases;
  volume plus 128-bit file identity detects a replaced partial.
- Validation holds the exact output with read/delete access and read sharing.
  Publication renames that held file without replacing an existing final.
  Cleanup deletes only a matching owned partial by handle; foreign replacements
  and unowned crash leftovers are retained.
- Initial native rename using RootDirectory plus a relative leaf failed with
  Win32 87 in unit and real integration checks. The final implementation uses
  an absolute path obtained from the held destination directory and a null
  RootDirectory. Rename remains by the held validated file handle, with
  ReplaceIfExists false.
- A read/write report guard was incompatible with PS5.1 Add-Content. A later
  metadata-only guard allowed Add-Content but failed the deletion protection
  assertion in both shells: 24 passed / 2 failed in each run. Final write-only
  access is compatible with Add-Content and makes denied delete sharing
  effective. The guard opens the leaf itself, rejects reparse points and
  multiple hardlinks, and retains the checked leaf through the report write.
- A focused direct check proved metadata-only destination directory access
  permitted a physical rename. Final GENERIC_READ access with no delete
  sharing blocks that rename. A regression test also verifies rename works
  after the transaction closes.
- Separate direct checks after that correction attempted Directory.Move on
  the destination's parent and on an input file's parent while their relevant
  handles were held. Both failed with access denied. Scratch artifacts were
  explicitly removed after disposing the handles. These were local Windows
  checks, not assertions about every filesystem or remote share.
